Power Pages & SPA (Part 2): Adding Authentication with Microsoft Entra ID

Welcome back to Hack the Platform!
In Part 1 of this series (Power Pages & SPA — Deploy React App), we built and deployed a React single-page application (SPA) to Power Pages using the PAC CLI, and configured it as a custom code site.

In this Part 2, we'll take our app a step further by adding authentication — enabling users to sign in with Microsoft Entra ID (formerly Azure AD) directly inside our SPA.

🎯 What We'll Cover in Part 2

In this part of the series, we will:

  • Configure Microsoft Entra ID as the default identity provider in Power Pages.
  • Disable local sign-in for simplicity and security.
  • Review how to preserve your configuration between deployments.
  • Build a custom authentication button component (login/logout).
  • Use Copilot to help us generate and improve the code.
  • Deploy and test the app again inside Power Pages.

By the end, your SPA will display a login button for anonymous users and show a personalized greeting when signed in — all powered by Power Pages' built-in authentication context.

⚙️ Step 1: Configure Microsoft Entra ID in Power Pages

Let's start by enabling Microsoft sign-in.

  1. Go to your Power Pages Design Studio.
  2. Select your website and open the Security section on the left.
  3. Choose Identity Providers.
  4. Turn on the Microsoft Entra ID provider.
  5. Disable Local Sign-in (optional, but recommended).
  6. Save your changes.

That's it — you don't need the Admin Center for this.
Power Pages will now use your Entra ID (Microsoft 365) accounts for authentication.

⚠️ Step 2: Backup Your Site Configuration

Before uploading a new SPA build, download your current site settings.
If you skip this step, Power Pages might overwrite your authentication setup during the next deployment.

Run this command in your project root:

pac pages download-code-site --path ./ --websiteid <your-site-id> --overwrite

💬 Step 3: Using Copilot for Help

I used Copilot to generate the authentication button component and integrate it into the site navigation. Here's the prompt I used:

Prompt for Copilot:
Generate for me the authentication button component and add it to the site navigation.
Style it nice and do not use MUI.
Use a GET request and redirect to /Account/Login instead of using a POST form.
Here is the code to use as a basis:

import { IconButton, Tooltip } from '@mui/material'
import { Login, Logout } from '@mui/icons-material'
import React from 'react'

export const AuthButton = () => {
  const username = (window as any)['Microsoft']?.Dynamic365?.Portal?.User?.userName ?? ''
  const firstName = (window as any)['Microsoft']?.Dynamic365?.Portal?.User?.firstName ?? ''
  const lastName = (window as any)['Microsoft']?.Dynamic365?.Portal?.User?.lastName ?? ''
  const isAuthenticated = username !== ''
  const [token, setToken] = React.useState<string>('')

  // @ts-ignore
  const tenantId = import.meta.env.VITE_TENANT_ID

  React.useEffect(() => {
    const getToken = async () => {
      try {
        const token = await (window as any).shell.getTokenDeferred()
        setToken(token)
      } catch (error) {
        console.error('Error fetching token:', error)
      }
    }
    getToken()
  }, [])

  return (
    <div className="flex items-center gap-4">
      {isAuthenticated ? (
        <>
          <span className="text-sm">Welcome {firstName + ' ' + lastName}</span>
          <Tooltip title="Logout">
            <IconButton
              color="primary"
              onClick={() => (window.location.href = '/Account/Login/LogOff?returnUrl=%2F')}
            >
              <Logout />
            </IconButton>
          </Tooltip>
        </>
      ) : (
        <form action="/Account/Login/ExternalLogin" method="post">
          <input name="__RequestVerificationToken" type="hidden" value={token} />
          <Tooltip title="Login">
            <IconButton
              name="provider"
              type="submit"
              color="primary"
              value={`https://login.windows.net/${tenantId}/`}
            >
              <Login />
            </IconButton>
          </Tooltip>
        </form>
      )}
    </div>
  )
}

Copilot did a great job — producing a simple, clean login/logout button styled with plain CSS, and using the Power Pages authentication context.

For more details on Power Pages authentication patterns, see: https://learn.microsoft.com/en-us/power-pages/configure/create-code-sites

🚀 Step 4: Build, Deploy, and Test

Rebuild your SPA:

npm run build

Then upload it back to Power Pages (same PAC CLI command as before).

✅ You'll now see:

  • Login button for anonymous users.
  • Welcome [User Name] + Logout for signed-in users.

Authentication — done! 🎉
