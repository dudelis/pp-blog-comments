🛠 Step 1: Enable Web API for the Account Table

Before your SPA can fetch Dataverse data, you must explicitly enable Web API access for the Account table using Power Pages site settings.
This configuration defines which tables and fields are exposed via the Power Pages Web API.

Go to your Power Pages → Site Settings, and create the following entries:

Site Setting NameDescriptionExample Value
Webapi/account/enabledEnables or disables Web API access for the account table.true
Webapi/account/fieldsDefines which attributes can be read or modified. Use * to allow all. Mandatory.*
Webapi/error/innererrorEnables inner error details in API responses (optional).true
Webapi/account/disableodatafilterEnables or disables OData filtering for the table (optional).false

📘 Note: If Webapi/<table name>/fields is missing, the Web API will throw an error:
“No fields defined for this entity.”

Once configured, your Power Pages Web API endpoint for the Account table will be available at:

https://your-site.powerappsportals.com/_api/accounts

You can find detailed documentation here:
👉 Power Pages Web API overview (Microsoft Learn)

🛠 Step 2: Configure Table Permissions for Account

Now that the Web API is enabled for the Account table, we need to control who can access it.
Since we want only authenticated users to fetch account data from our SPA, we must configure table permissions.

  1. Open your Power Pages Studio.
  2. Go to Security → Table Permissions.
  3. Find the Account table.
  4. Add a new permission rule:
    • Permission Scope: Organization
    • Access Rights: Read
    • Applies To: Authenticated Users

🔹 This ensures that anonymous visitors will get a 403 Forbidden response if they try to access the Account API, while authenticated users (who logged in via the method we configured in Part 2) will succeed.

  1. Save your changes.

By doing this, we are effectively linking authentication to data access, which allows our SPA to securely fetch data using the CSRF token obtained via the shell.getTokenDeferred() or the AJAX helper function we’ll create in Step 3.

🛠 Step 3: Add Secure Fetch Logic in React

To fetch data from the Power Pages Web API securely, we need to handle the CSRF token.
Instead of using jQuery, we’ll create a reusable AJAX helper in React.

🔹 Reference: This approach is adapted from Microsoft documentation on handling Web API HTTP requests and errors:
Power Pages Web API HTTP Requests and Handle Errors

3.1 Create webapi.ts in the lib folder

// lib/webapi.ts
interface TokenDeferredLike {
  done: (cb: (token: string) => void) => {
    fail: (cb: (error: unknown) => void) => void
  }
  fail: (cb: (error: unknown) => void) => void
}

declare global {
  interface Window {
    shell?: {
      getTokenDeferred: () => TokenDeferredLike
    }
  }
}

export interface SafeFetchOptions {
  url: string
  method?: string
  headers?: Record<string, string>
  signal?: AbortSignal
}

// Fetch JSON with token header
export async function safeFetch<T = unknown>({
  url,
  method = 'GET',
  headers = {},
  signal,
}: SafeFetchOptions): Promise<T> {
  const shell = window.shell
  if (!shell || typeof shell.getTokenDeferred !== 'function') {
    throw new Error('window.shell.getTokenDeferred unavailable')
  }

  const token: string = await new Promise((resolve, reject) => {
    try {
      shell
        .getTokenDeferred()
        .done((t: string) => resolve(t))
        .fail(() => reject(new Error('Token acquisition failed')))
    } catch (e) {
      reject(e)
    }
  })

  const mergedHeaders: Record<string, string> = {
    __RequestVerificationToken: token,
    Accept: 'application/json',
    ...headers,
  }

  const resp = await fetch(url, { method, headers: mergedHeaders, signal })
  if (!resp.ok) {
    const text = await resp.text().catch(() => '')
    throw new Error(`HTTP ${resp.status} ${resp.statusText} - ${text}`)
  }
  const contentType = resp.headers.get('content-type') || ''
  if (contentType.includes('application/json')) {
    return resp.json()
  }
  return (await resp.text()) as unknown as T
}

export const webapi = { safeFetch }

🔹 Tip: This function retrieves the CSRF token from window.shell.getTokenDeferred(), then attaches it as a header to your fetch request.
This ensures that all API calls to your Power Pages endpoints are authenticated and safe.

You can now use webapi.safeFetch throughout your SPA to request data from any enabled table.

4.3 Create Accounts.tsx Page and Add to Router

Now, create a new page to fetch accounts and render them using AccountCard.
Remember to import webapi.safeFetch and use the CSRF token for secure requests.

// src/pages/Accounts.tsx
import React, { useEffect, useState } from 'react';
import { AccountCard, Account } from '../components/AccountCard';
import { webapi } from '../lib/webapi';

export const Accounts: React.FC = () => {
  const [accounts, setAccounts] = useState<Account[]>([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const fetchAccounts = async () => {
      try {
        const data = await webapi.safeFetch<Account[]>({
          url: '/_api/accounts',
        });
        setAccounts(data);
      } catch (error) {
        console.error('Error fetching accounts:', error);
      } finally {
        setLoading(false);
      }
    };
    fetchAccounts();
  }, []);

  if (loading) return <p>Loading accounts...</p>;
  if (accounts.length === 0) return <p>No accounts found.</p>;

  return <div className="accounts-grid">{accounts.map(a => <AccountCard key={a.accountid} account={a} />)}</div>;
};

🛠 Step 6: Download Site Configuration and Upload SPA

Before uploading our updated SPA to Power Pages, we need to preserve site settings to avoid overwriting important configurations like table API access and authentication.

🔹 Full details on downloading and uploading site configurations are described in Part 1 of this series.

6.1 Download Current Site Configuration

Run the following command (adjust --websiteid to your site ID):

pac pages download-code-site --path ./ --websiteid <YourSiteID> --overwrite

🔹 This ensures you have a local copy of the site configuration.
Important: If you skip this step, uploading the SPA will overwrite all settings, including web API permissions, authentication configuration, and other site settings.

6.2 Upload Updated SPA with Preserved Settings

Once you have the configuration downloaded, upload your SPA:

pac pages upload-code-site --rootPath ./mypowerpagesspa/ --compiledPath ./dist --siteName "MyPowerPagesSPA"

🔹 Note: After the first deployment, it may take 5–10 minutes for the site to become fully available.
You might see an error or a “Something went wrong” message initially — just be patient.

6.3 Test the SPA

  1. Open the SPA as an anonymous user:
    • You should see 403 Forbidden for the Accounts page, because read access is restricted to authenticated users.
  2. Log in using the authentication button configured in Part 2.
    • You should now be able to access the Accounts page and see the data fetched from the Account table.

🔹 This confirms that both authentication and secure fetch logic are working correctly.
