Power Pages & SPA (Part 1): Deploying a Custom React SPA to Microsoft Power Pages

Welcome to Hack the Platform — where we take the Power Platform to its limits and beyond.

In this post, we’ll build and deploy a Single Page Application (SPA) using React + Vite and host it on Microsoft Power Pages.
You’ll learn how to upload it with the official Power Platform CLI (PAC) and how to safely re-upload without losing your configuration.

🧭 Summary

In this tutorial, you’ll learn how to:

  • Create a React + TypeScript SPA using Vite
  • Understand why HashRouter is essential for Power Pages
  • Deploy your SPA using the official PAC CLI
  • Handle first-deployment quirks
  • Troubleshoot JavaScript file restrictions
  • Download and re-upload your site while preserving configuration

🧰 Prerequisites

Before we begin, make sure you have:

  • Node.js
  • Power Platform CLI
node -v
npm -v
pac

⚙️ Step 1: Create a New React + TypeScript App with Vite

We’ll use Vite to scaffold a modern React + TypeScript app.

npm create vite@latest powerpages-spa -- --template react-ts
cd powerpages-spa
npm install
npm run dev

Now open your browser at http://localhost:5173 and you’ll see your new React app running.

🧭 Step 2: Add Pages and Navigation

Let’s add some basic structure: two simple pages (Home and Products) with navigation.

Create a folder src/pages/ and add these files:

src/pages/Home.tsx

const Home = () => (
  <div>
    <h2>Welcome to our SPA on Power Pages!</h2>
  </div>
);
export default Home;

src/pages/Products.tsx

const Products = () => (
  <div>
    <h2>Products</h2>
    <p>This is our product list page.</p>
  </div>
);
export default Products;

🪝 Step 3: Use HashRouter (Critical for Power Pages)

Power Pages handles routing on the server side.
If you use BrowserRouter, your SPA will break on refresh or navigation, because Power Pages tries to resolve routes itself.

To fix that, use HashRouter — it keeps navigation fully on the client side, avoiding any routing conflicts.

src/App.tsx

import { HashRouter as Router, Route, Routes, NavLink } from 'react-router-dom';
import reactLogo from './assets/react.svg';
import viteLogo from '/vite.svg';
import './App.css';
import Home from './pages/Home';
import Products from './pages/Products';

function App() {
  return (
    <Router>
      <div className="app">
        <header className="header">
          <div className="header-content">
            <div className="logo-section">
              <a href="https://vite.dev" target="_blank">
                <img src={viteLogo} alt="Vite logo" />
              </a>
              <a href="https://react.dev" target="_blank">
                <img src={reactLogo} alt="React logo" />
              </a>
              <h1>My Power Pages SPA</h1>
            </div>
            <nav className="navigation">
              <NavLink to="/" end>Home</NavLink>
              <NavLink to="/products">Products</NavLink>
            </nav>
          </div>
        </header>
        <main className="main-content">
          <Routes>
            <Route path="/" element={<Home />} />
            <Route path="/products" element={<Products />} />
          </Routes>
        </main>
      </div>
    </Router>
  );
}

export default App;

🏗️ Step 4: Build and Deploy to Power Pages

Let’s deploy your app to Power Pages using Power Platform CLI.

🧱 Build for production

npm run build

This generates your optimized files inside the dist/ folder.

🔐 Authenticate to Power Platform

pac auth create --url https://yourorg.crm.dynamics.com

Replace the URL with your actual Dataverse environment address.

📤 Upload your SPA

pac pages upload-code-site --rootPath ./ --compiledPath ./dist --siteName "MyPowerPagesSPA"

This uploads your compiled React app to Power Pages.

⚠️ Step 5: Fix JavaScript Upload Restrictions

If you see errors when uploading, your environment may block JavaScript files.

To fix this:

  1. Go to your Power Platform environment
  2. Open Advanced Settings
  3. Navigate to Administration → System Settings
  4. Find the Blocked File Extensions list
  5. Remove .js from that list
  6. Save and retry the upload

After that, rerun your upload command — it should complete successfully.

💾 Step 6: Download Your Site (Preserve Configuration)

Each upload overwrites site configuration — authentication, permissions, and more.
To prevent that, download your current configuration before re-uploading.

pac pages list

pac pages download-code-site --path ./ --websiteid "YOUR SITE GUID" --overwrite

Replace the website ID with your actual Power Pages site GUID.
This downloads both code and configuration locally.

🔁 Step 7: Re-Upload While Preserving Settings

When you’re ready to re-deploy updates, use this command to keep your site settings intact:

pac pages upload-code-site --rootPath ./mypowerpagesspa/ --compiledPath ./dist --siteName "MyPowerPagesSPA"

This safely updates your SPA files without touching existing Power Pages configurations.

🚀 Step 8: Activate Your Site

Once uploaded, go to:

Power Pages Admin Center → Sites → Inactive Sites

Select your new site and click Activate — your React SPA is now live!

After the first upload, your site may take 5–10 minutes to activate.
You might see “Something went wrong” at first — don’t worry, that’s expected.
Power Pages is still processing and provisioning your site.

Grab a coffee ☕ and refresh in a few minutes — it’ll be ready.
