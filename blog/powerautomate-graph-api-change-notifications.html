Subscribe to Microsoft Graph API Notifications with Power Automate

In this post, I’m showing how I subscribe to Microsoft Graph API notifications using Power Automate to monitor Microsoft Entra ID user changes in real time.

This approach is great because it allows me to:

  • Build event-driven workflows without writing backend code
  • Receive instant notifications for user updates, like profile changes, department updates, or account enable/disable
  • Automate audits, notifications, and integrations directly from Power Automate
  • Avoid slow and inefficient polling of the Graph API

I’ll walk you step by step through creating the subscription, handling notifications, and retrieving updated user data — all inside Power Automate.

Use Case

A customer asked if it's possible to get real-time events for Entra ID users without polling. Specifically, they wanted to detect:

  • Profile updates
  • Department or job title changes
  • Account enable/disable
  • Any attribute change

Polling the Graph API every few minutes is slow and inefficient. The solution? Graph change notifications sent directly to Power Automate. Unfortunately, there is no trigger in the Office 365 Users connector—or any other connector—for user profile changes, so webhooks via Microsoft Graph are required for real-time detection.

Architecture Overview

We’ll create two flows:

Flow 1 – Create the Subscription

  • You can use any tool: Graph Explorer, Postman, CLI, or code.
  • Here, we use Power Automate to keep it low-code.
  • A subscription is valid for 4230 minutes (~70.5 hours), so make this flow recurring to renew/update it.

Flow 2 – Receive Notifications

  • Receives HTTP calls from Graph when a user changes.
  • Handles validationToken handshake (must respond within 10 seconds).
  • Processes real notifications to extract user IDs and trigger logic.

App Registration

To call Microsoft Graph from Power Automate using HTTP actions, create an Entra ID App Registration with Application Permissions, because everything runs in the background.

Required permissions:

  • User.Read.All

Steps:

  1. Create a new App Registration
  2. Add Application Permissions
  3. Grant Admin Consent
  4. Create a client secret
  5. Use credentials in Power Automate HTTP actions

Flow 1 – Creating the Subscription

Add an HTTP action:

POST https://graph.microsoft.com/v1.0/subscriptions
Content-Type: application/json

{
  "changeType": "updated",
  "notificationUrl": "https://prod-YOUR-REGION.logic.azure.com:443/.../flows/YOUR-FLOW-ID",
  "resource": "users",
  "expirationDateTime": "2025-01-01T00:00:00.000Z",
  "clientState": "MySuperSecretState"
}

Notes:

  • changeType: "updated" ensures all user updates trigger notifications
  • notificationUrl points to Flow 2
  • The subscription lifetime is 4230 minutes, so renew it regularly

Flow 2 – Handling Notifications

Trigger: When an HTTP request is received

Case 1: validationToken

Graph sends a validationToken query parameter for subscription validation.

  • Respond within 10 seconds
  • Return the token in plain text
Status Code: 200
Body: @{triggerOutputs()?['queries']?['validationToken']}

Case 2: Actual User Change Notification

Sample payload:

{
  "value": [
    {
      "changeType": "updated",
      "clientState": "MySuperSecretState",
      "resource": "Users/cbe0e210-f39d-406d-974c-e581932356eb",
      "resourceData": {
        "@odata.type": "#Microsoft.Graph.User",
        "@odata.id": "Users/cbe0e210-f39d-406d-974c-e581932356eb",
        "id": "cbe0e210-f39d-406d-974c-e581932356eb",
        "organizationId": "1e7886bb-4ad8-4924-b559-29c5f5fea8f5"
      },
      "subscriptionExpirationDateTime": "2025-12-19T16:00:00-08:00",
      "subscriptionId": "c335af10-0431-4c53-98f9-301f4a46c5ac",
      "tenantId": "1e7886bb-4ad8-4924-b559-29c5f5fea8f5"
    }
  ]
}

Testing

  1. Run Flow 1 to create/renew the subscription
  2. Confirm Flow 2 responds to validationToken
  3. Update a user in Entra ID:
    • Change job title
    • Update department
    • Enable or disable the account
  4. Flow 2 triggers immediately
  5. Verify the user ID and retrieve details

Summary

In this tutorial, we covered:

  • Using Microsoft Graph change notifications to detect Entra ID user updates
  • Creating Power Automate flows to handle subscriptions and notifications
  • Responding to the 10-second validationToken handshake
  • Fetching updated user details from Office 365 Users Connector.

This setup allows real-time monitoring of Entra ID users completely inside Power Automate, no Azure Functions required.
