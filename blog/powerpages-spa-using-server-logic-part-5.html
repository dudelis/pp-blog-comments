Using Server Logic in React SPA

Konstantin Fukszon · November 20, 2025

This is Part 5 of the Power Pages & SPA series.
In this part, we take a React SPA to the next level by integrating Power Pages Server Logic for secure server-side execution.
We will use Microsoft Entra ID credentials stored in Environment Variables → Site Settings, keeping secrets out of the frontend and ensuring an ALM-friendly setup.

📝 Overview & Use Case

In this tutorial, we will implement a solution that allows authenticated users of our React SPA to retrieve all Microsoft Entra ID groups that the user belongs to.

The use case:

We want to display a list of groups for a specific user in a SPA page, ensuring:

  • Only authenticated users can request this information
  • No secrets (Client ID, Client Secret) are exposed in the frontend
  • Permissions are properly scoped using Microsoft Entra ID application permissions

Required Microsoft Graph API permissions (Application type):

  • User.Read.All — to read user properties
  • Group.Read.All — to read all group memberships in the tenant

This allows our Server Logic to query /users/{id}/memberOf as an application without a signed-in user context.

📝 Part 5 Plan

Here’s what we’ll do step by step:

1️⃣ App Registration

Create a Microsoft Entra ID app registration that your Server Logic will use for app-only (client credentials) access to Microsoft Graph:

  • Assign application permissions:
    • User.Read.All
    • Group.Read.All
  • Record the Client ID and create a Client Secret (store both securely in environment variables / site settings)
  • These credentials allow Server Logic to get an access token and call: https://graph.microsoft.com/v1.0/users/{userId}/memberOf to retrieve the user's group memberships.

2️⃣ Environment Variables & Site Settings Configuration

We do not hard‑code any Microsoft Entra ID credentials. Instead we externalize them so they can change per environment (dev / test / prod) without touching code.

Why this matters:

  • Keeps secrets off the frontend
  • Supports rotation without redeploying SPA assets
  • Fits cleanly into ALM and solution transport
  • Enables different values per environment automatically

What we create:

  • Environment Variable: Graph Client ID
  • Environment Variable: Graph Client Secret
  • Environment Variable: Tenant ID

How they flow:

  1. Add each value as an Environment Variable in the Power Pages solution.
  2. Create Site Settings with names that match what Server Logic will read:
  • SL-TenantID
  • SL-ClientID
  • SL-ClientSecret
  1. Server Logic reads these at runtime (server side only).
  2. React SPA never sees or ships these values.

Result:

  • Server Logic can securely request Microsoft Graph tokens.
  • Frontend stays clean: no embedded secrets, no accidental leaks.
  • You can promote the solution (including the SPA) and only update the environment variable values, not the code.

3️⃣ Server Logic Implementation

This step adds a secure server-side JavaScript function in Power Pages that runs only for authenticated users. It will:

  • Read the Microsoft Entra ID application credentials (Client ID, Client Secret, Tenant ID) from Power Pages Site Settings (mapped from Environment Variables).
  • Use the client credentials (application) flow to request an access token from Entra ID.
  • Call the Microsoft Graph API endpoint: https://graph.microsoft.com/v1.0/users/{userId}/memberOf to retrieve all directory groups the target user is a member of.
  • Return a trimmed JSON list containing each group’s displayName and id.
  • Log meaningful errors server-side without exposing secrets.
  • Prevent unauthenticated access.

Generate a JavaScript function for Power Pages Server Logic that:

- Runs inside Power Pages Server Logic and is exposed as /\_api/serverlogic/groups
- Allows only authenticated users
- Uses the logged-in user’s email from `Server.User.emailaddress1` (do NOT use query parameters)
- Reads Microsoft Entra ID App Registration credentials from Site Settings:
  - SL-TenantID
  - SL-ClientID
  - SL-ClientSecret
- Implements Microsoft-style client credentials flow to get an access token:
  - Use a JSON body with keys: client_id, client_secret, scope, grant_type
  - Send the request to `https://login.microsoftonline.com/{TENANT_ID}/oauth2/v2.0/token`
  - Use `application/x-www-form-urlencoded` as content type
  - Parse the response using `JSON.parse(JSON.parse(response).Body)`
- Calls Microsoft Graph API:
  - First resolve userId from `https://graph.microsoft.com/v1.0/users/{userEmail}`
  - Then call `https://graph.microsoft.com/v1.0/users/{userId}/memberOf`
- Returns a JSON response with:
  - status: "success"
  - userEmail
  - groups: array of objects with id and displayName
- Includes proper error handling and server-side logging using `Server.Logger`
- Follows Power Pages Server Logic best practices
- Use double JSON.parse for HttpClient responses as required by Power Pages
- Do NOT use query parameters anywhere
- The final code should look like this structure:

Server Logic Code

async function get() {
try {
// ✅ Ensure user is authenticated
const userEmail = Server.User.emailaddress1;
if (!userEmail) {
const errorMsg = "Unauthorized: User is not authenticated.";
Server.Logger.Error(errorMsg);
return JSON.stringify({ status: "error", message: errorMsg });
}

        Server.Logger.Log(`Authenticated user: ${userEmail}`);

        // ✅ Read Site Settings for Entra ID credentials
        const TENANT_ID = Server.SiteSetting.Get("SL-TenantID");
        const CLIENT_ID = Server.SiteSetting.Get("SL-ClientID");
        const CLIENT_SECRET = Server.SiteSetting.Get("SL-ClientSecret");

        if (!TENANT_ID || !CLIENT_ID || !CLIENT_SECRET) {
            const errorMsg = "Missing required Microsoft Entra ID credentials in Site Settings.";
            Server.Logger.Error(errorMsg);
            return JSON.stringify({ status: "error", message: errorMsg });
        }

        // ✅ Step 1: Acquire token using Client Credentials Flow (MS style body)
        const tokenBody = {
            "client_id": CLIENT_ID,
            "client_secret": CLIENT_SECRET,
            "scope": "https://graph.microsoft.com/.default",
            "grant_type": "client_credentials"
        };

        const tokenResp = await Server.Connector.HttpClient.PostAsync(
            `https://login.microsoftonline.com/${TENANT_ID}/oauth2/v2.0/token`,
            JSON.stringify(tokenBody),
            { "Content-Type": "application/x-www-form-urlencoded" },
            "application/x-www-form-urlencoded"
        );

        if (!tokenResp || JSON.parse(tokenResp).StatusCode !== 200) {
            const errorMsg = `Failed to acquire token. Status: ${tokenResp.StatusCode}`;
            Server.Logger.Error(errorMsg);
            return JSON.stringify({ status: "error", message: errorMsg });
        }

        const tokenJson = JSON.parse(JSON.parse(tokenResp).Body);
        const accessToken = tokenJson.access_token;
        if (!accessToken) {
            const errorMsg = "Access token not found in response.";
            Server.Logger.Error(errorMsg);
            return JSON.stringify({ status: "error", message: errorMsg });
        }

        // ✅ Step 2: Resolve userId from userEmail using Graph API
        const userLookupUrl = `https://graph.microsoft.com/v1.0/users/${userEmail}`;
        const graphHeaders = {
            "Authorization": `Bearer ${accessToken}`,
            "Content-Type": "application/json"
        };

        const userLookupResp = await Server.Connector.HttpClient.GetAsync(userLookupUrl, graphHeaders);

        const userData = JSON.parse(JSON.parse(userLookupResp).Body);
        const userId = userData.id;
        if (!userId) {
            const errorMsg = "User ID not found in Graph response.";
            Server.Logger.Error(errorMsg);
            return JSON.stringify({ status: "error", message: errorMsg });
        }

        Server.Logger.Log(`Resolved userId: ${userId}`);

        // ✅ Step 3: Call Microsoft Graph API to get groups
        const memberOfUrl = `https://graph.microsoft.com/v1.0/users/${userId}/memberOf`;
        const memberOfResp = await Server.Connector.HttpClient.GetAsync(memberOfUrl, graphHeaders);


        const memberOfData = JSON.parse(JSON.parse(memberOfResp).Body);
        const groups = (memberOfData.value || []).map(g => ({
            id: g.id,
            displayName: g.displayName
        }));

        // ✅ Return JSON response
        return JSON.stringify({ status: "success", userEmail: userEmail, groups: groups });

    } catch (err) {
        Server.Logger.Error("GET failed: " + err.message);
        return JSON.stringify({ status: "error", message: err.message });
    }

}

4️⃣ React SPA Integration

In this part we add a new React SPA page that calls the secured Power Pages Server Logic endpoint /api/groups. The page will request the signed‑in user’s Microsoft Entra ID group memberships through the server (not directly from the browser), ensuring secrets remain server-side.

Flow summary:

  1. User navigates to the SPA page while authenticated.
  2. React component issues a fetch to /api/serverlogics/groups.
  3. The request includes the required anti-forgery (CSRF) token exactly as established in Part 3’s data fetching pattern (we reuse the same header/cookie approach—no code repeated here).
  4. Server Logic validates authentication, reads the app credentials from Site Settings, obtains a Graph token via client credentials, calls Microsoft Graph for the user’s groups, and returns a minimal JSON list (id + displayName).
  5. React renders loading state, success list, or a friendly error.

No secrets ever appear in the frontend and the CSRF protection pattern from Part 3 is consistently applied.

React SPA Code - Groups.tsx:

import React from 'react'
import { safeFetch } from '../lib/webapi'

// Group interface based on expected response from /\_api/groups
interface Group {
id: string;
displayName: string;
}

// Server Logic response structure
interface ServerLogicResponse {
requestId: string;
success: boolean;
data: string; // JSON string that needs to be parsed
serverLogicName: string;
}

// Parsed data structure from the data field
interface GroupsData {
status: string;
userEmail: string;
groups: Group[];
}

const fetchGroups = async (): Promise<Group[]> => {
const response = await safeFetch<ServerLogicResponse>({
url: '/\_api/serverlogics/groups'
});

if (!response.success) {
throw new Error('Server logic request failed');
}

// Parse the JSON string in the data field
const parsedData: GroupsData = JSON.parse(response.data);

const groups: Group[] = parsedData.groups || [];
return groups
.filter((g: Group) => g.displayName)
.sort((a, b) => a.displayName.localeCompare(b.displayName));
};

const Groups: React.FC = () => {
const [groups, setGroups] = React.useState<Group[]>([]);
const [loading, setLoading] = React.useState<boolean>(true);
const [error, setError] = React.useState<string | null>(null);
const [refetchTick, setRefetchTick] = React.useState<number>(0);

React.useEffect(() => {
let cancelled = false;
const load = async () => {
setLoading(true);
setError(null);
try {
const data = await fetchGroups();
if (!cancelled) {
setGroups(data);
}
} catch (e: unknown) {
if (!cancelled) {
const message = e instanceof Error ? e.message : 'Failed to load groups';
setError(message);
}
} finally {
if (!cancelled) setLoading(false);
}
};
load();
return () => { cancelled = true; };
}, [refetchTick]);

const onRefresh = () => setRefetchTick(t => t + 1);

return (

<div style={{ textAlign: 'left' }}>
<h2>Groups</h2>
<div style={{ display: 'flex', gap: '0.75rem', alignItems: 'center', flexWrap: 'wrap' }}>
<button onClick={onRefresh} style={refreshButtonStyle} title="Refresh groups">Refresh</button>
{loading && <span style={{ fontSize: '0.75rem', opacity: 0.8 }}>Loading...</span>}
{!loading && !error && <span style={{ fontSize: '0.7rem', opacity: 0.7 }}>Showing {groups.length} group(s)</span>}
{error && <span style={{ color: '#ff6b6b', fontSize: '0.75rem' }}>{error}</span>}
</div>

      {!loading && groups.length === 0 && !error && (
        <p style={{ fontSize: '0.85rem', opacity: 0.8 }}>No groups found.</p>
      )}

      {error && !loading && (
        <div style={errorBoxStyle}>
          <strong>Error:</strong> {error}
        </div>
      )}

      <div style={groupsGridStyle}>
        {groups.map(group => (
          <div key={group.id} style={groupCardStyle}>
            <div style={groupNameStyle}>{group.displayName}</div>
            <div style={groupIdStyle}>ID: {group.id}</div>
          </div>
        ))}
      </div>
    </div>

);
};

const refreshButtonStyle: React.CSSProperties = {
background: 'linear-gradient(135deg,#646cff,#747bff)',
color: '#fff',
padding: '0.5rem 0.9rem',
border: 'none',
borderRadius: '6px',
cursor: 'pointer',
fontSize: '0.75rem',
fontWeight: 500,
letterSpacing: '0.5px',
boxShadow: '0 2px 4px rgba(0,0,0,0.25)',
transition: 'transform 0.2s ease, box-shadow 0.2s ease',
};

const errorBoxStyle: React.CSSProperties = {
marginTop: '1rem',
padding: '1rem',
backgroundColor: '#fee',
border: '1px solid #fcc',
borderRadius: '6px',
color: '#c33',
fontSize: '0.85rem',
};

const groupsGridStyle: React.CSSProperties = {
marginTop: '1.5rem',
display: 'grid',
gridTemplateColumns: 'repeat(auto-fill, minmax(280px, 1fr))',
gap: '1rem',
};

const groupCardStyle: React.CSSProperties = {
padding: '1rem',
backgroundColor: 'rgba(255, 255, 255, 0.05)',
border: '1px solid rgba(255, 255, 255, 0.1)',
borderRadius: '8px',
transition: 'all 0.2s ease',
cursor: 'default',
