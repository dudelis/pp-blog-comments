How to Delete AgentBuilder Agents Automatically

Organizations that adopt Microsoft 365 Copilot quickly discover that users can create AgentBuilder agents directly from the Copilot interface. These agents are created using the Copilot Studio Live experience and do not follow the typical lifecycle used for managed Copilot Studio agents.

For many companies this creates a governance gap. Administrators cannot currently prevent users from creating AgentBuilder agents while still allowing access to approved first-party or third-party agents.

The available setting in Microsoft 365 Copilot either allows all agents or blocks them entirely.

This leaves organizations with limited options if they want proper governance, visibility, and tenant hygiene.

In this article we implement a reactive governance approach:
we periodically scan the Power Platform Inventory and automatically delete AgentBuilder agents that appear in the tenant.

This allows administrators to keep their environment clean while still allowing Microsoft and third-party agents to be used.

Understanding the Governance Problem

When users create agents via Copilot Studio Lite (AgentBuilder), these agents do not behave like traditional Copilot Studio bots.

Several characteristics make governance difficult:

  • They are not visible inside the Default environment
  • They appear in the Power Platform Inventory
  • They are associated with the Default environment or with Microsoft 365 environment
  • Administrators cannot selectively disable their creation

Inside Microsoft 365 Copilot settings, administrators can configure User Access to agents.

However, this control is too coarse.

If you configure:

No Users →

  • Users cannot create agents
  • Users also cannot use any first-party or third-party agents

For many organizations this is not acceptable because they still want users to consume approved agents.

This is where a reactive governance model becomes useful.

Solution Overview

Instead of preventing creation, we implement an automated cleanup process.

The idea is simple:

  1. Query the Power Platform Inventory
  2. Retrieve all Copilot Studio agents, by filtering for AgentBuilder agents
  3. Iterate through the list
  4. Delete each agent using the Power Platform for Admins V2 connector

This can run on a schedule so that unauthorized agents are automatically removed.

Environment Assumptions

AgentBuilder agents appear in the inventory as belonging to the Default environment, even though they are not visible when you open that environment.

How AgentBuilder Agents Appear in Inventory

When querying the Power Platform Inventory, AgentBuilder agents appear as Copilot Studio agents. You can verify this behavior in Power Platform Admin Center (PPAC).

Even though the agents are tied to the Default environment, they cannot be opened there. This behavior is important to understand when building automation around them.

Building the Power Automate Flow

The automation is implemented using Power Automate and the Power Platform Admin V2 connector.

High-level flow:

  1. Query Power Platform resources, filtering the results
  2. Iterate through each agent
  3. Delete the agent

This flow can be triggered manually or scheduled to run periodically.

Inventory Query Configuration

The first step queries the Power Platform Inventory.

Table

PowerPlatformResources

Clauses

[
  {
    "$type": "where",
    "FieldName": "type",
    "Operator": "in~",
    "Values": ["'microsoft.copilotstudio/agents'"]
  }
]

In practice you will add additional clauses.

For example:

  • Filter for AgentBuilder agents
  • Optionally filter for Default environment

Example structure with multiple clauses:

[
  {
    "$type": "where",
    "FieldName": "type",
    "Operator": "in~",
    "Values": ["'microsoft.copilotstudio/agents'"]
  },
  {
    "$type": "where",
    "FieldName": "properties.createdIn",
    "Operator": "==",
    "Values": ["'Copilot Studio Lite'"]
  }
]

⚠️ Important: Mind the single quotes inside the double quotes in the filter values. Without them, the query will not work.

"Values": ["'microsoft.copilotstudio/agents'"]

Notice the quotes: outer double quotes for the JSON value, inner single quotes for the string literal.

You can refine this query later if you want to target only specific agents.

Deleting the Agents

Once the agents are retrieved, iterate through them and call the Delete a bot in Copilot Studio action from the Power Platform Admin V2 connector.

Required parameters:

  • Environment ID → properties.environmentId the environment of an agent or in our case - Default environment
  • Bot ID → name property from the inventory results

Example logic:

For each agent
  Delete a bot
    EnvironmentId = properties.environmentId
    BotId = name

When the action runs, the agent is removed immediately from Microsoft 365 Copilot.

Pitfalls and Operational Considerations

Inventory Is Not Real-Time

The Power Platform Inventory API has a delay of approximately 10–15 minutes.

This means:

  • After an agent is created, it may take 10–15 minutes before it appears in inventory
  • After an agent is deleted, it may still appear in inventory for another 10–15 minutes

When implementing automation, take this into account.

For example:

  • Do not run the cleanup flow too frequently
  • Expect temporary discrepancies in the inventory results

Deleted Agents May Still Appear Temporarily

Because of the inventory delay, agents may appear even after they are deleted. This is normal behavior.

Required Permissions

The Power Platform Admin connector requires elevated permissions. Exact role requirements should be verified in your tenant.

Summary

AgentBuilder agents created through Copilot Studio Live can introduce governance challenges because administrators cannot selectively disable their creation.

By leveraging the Power Platform Inventory API and the Power Platform Admin connector, we can implement a simple automation that detects and removes these agents.

This reactive governance approach allows organizations to:

  • Maintain tenant hygiene
  • Control unauthorized agents
  • Keep approved agents available to users

Try implementing this flow in your tenant.

Extend the logic with approval conditions if you need more control, and consider packaging the flow so it can be reused across environments.

You can also provide a downloadable version of the flow so that teams can deploy the automation quickly.
